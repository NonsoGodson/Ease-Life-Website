## CONTRAST-CHECKER GOTCHA (important)
The automated test's contrast checker reads `background-color` walking up the DOM and IGNORES background IMAGES and gradients, and treats `bg-white/NN` as solid #ffffff (ignoring alpha). So:
- Any section with white text over an image/gradient MUST have a solid dark `background-color` ancestor (e.g. add `bg-navy` to the hero section; `.navy-gradient` includes background-color).
- Do NOT put white text on `bg-white/10` etc. Use `bg-transparent` + border instead (transparent resolves up to the navy ancestor).
- Avoid semi-transparent text colors like `text-white/85` for large paragraphs on dark bg — the checker mis-reads them. Use a solid light color (e.g. `text-slate-200`).

- IMPORTANT: parenthesized route-group subdirs must be `mkdir -p`'d in bash BEFORE batch_file_write.

## CRM / leads
- Prisma: User (role default "user"; "admin" for staff) + Lead (name,email,phone,serviceCategory,serviceLabel,message,status LeadStatus enum NEW/CONTACTED/QUOTED/PAID/DELIVERED default NEW, source, attachmentPath, attachmentName, adminNotes, timestamps).
- API: POST /api/leads (public create + sends 2 emails: confirmation to submitter + alert to easelifeventures@gmail.com; sender_email=noreply@<hostname>). GET /api/leads (admin: status/category/search filters + statusCounts). PATCH /api/leads/[id] (admin status/notes). GET /api/leads/[id] (admin signed attachment URL). POST /api/upload/presigned (private S3 attachment).
- Auth: NextAuth v4 JWT + CredentialsProvider (bcrypt). authOptions in lib/auth.ts, pages.signIn='/login'. Admin dashboard guarded by app/admin/layout.tsx (getServerSession → redirect /login if role!=='admin'). Public signup exists (/api/signup) but creates role 'user' (no admin access) and is intentionally NOT surfaced in UI — /login is admin-only.
- Hidden seeded admin/test account credentials are in scripts/seed.ts — NEVER surface to the user.
- Notification env: WEB_APP_ID, NOTIF_ID_LEAD_CONFIRMATION (USER, critical), NOTIF_ID_NEW_LEAD_ALERT (ADMIN, critical).
